# Contributing to PyControlCharts

## Development setup

Use a virtual environment (e.g. `.venv`) and install in editable mode with dev dependencies:

```bash
python -m venv .venv
source .venv/bin/activate 
pip install -e ".[dev]"
```

For Plotly-related work, also install the plotly extra:

```bash
pip install -e ".[dev,plotly]"
```

## Running tests

```bash
pytest tests/ -v
```

With coverage:

```bash
pytest --cov=pycontrolcharts tests/
```

## Linting

The project uses [Ruff](https://docs.astral.sh/ruff/). Run from the repo root:

```bash
ruff check src/ tests/
```

To auto-fix fixable issues:

```bash
ruff check src/ tests/ --fix
```

To format code (if using Ruff format):

```bash
ruff format src/ tests/
```

Run both check and format before submitting (see [Development workflow](#development-workflow)).

## Project structure

### Repository layout

- **`images/`** — PNGs used in README and USER_GUIDE (e.g. `XbarR_chart.png`, `example_chart_01.png`, `xmr_chart.png`, `xmr_multi_phase.png`, `XbarS_run_tests.png`).
- **`scripts/`** — Dev/validation scripts (see [Scripts](#scripts)).
- **`src/pycontrolcharts/`** — Package source.
- **`tests/`** — Pytest suite.
- Key files: `README.md`, `USER_GUIDE.md`, `API.md`, `pyproject.toml`, etc.
- **`chart_output/`** — Generated by scripts; not committed (in `.gitignore`).

### Code structure

- **`src/pycontrolcharts/charts/`** — One module per chart type (`xmr`, `xbar_r`, `xbar_s`, `p_chart`, `np_chart`, `c_chart`, `u_chart`). Each exposes a single `calc_*` function.
- **`src/pycontrolcharts/plotting/`** — Plotly integration; `plot_control_chart()` and helpers.
- **`src/pycontrolcharts/models.py`** — `RunTestConfig`, `ChartType`, `RunType` (enums/dataclasses for run tests and chart type selection).
- **`src/pycontrolcharts/`** — Shared pieces: `input_handlers`, `output_builder`, `core` (run tests), `chart_helpers`, `constants`.

## Scripts

All scripts are intended to be run from the **repository root**. The directory `chart_output/` is the default output for scripts that write HTML/CSV/JSON; it is in `.gitignore`.

| Script | Purpose | When to use | Invocation | Output |
|--------|---------|-------------|------------|--------|
| **drive_reference_charts.py** | Renders USPC/GTDA reference charts to HTML (and optionally CSV) for visual inspection. | After changing chart/plot logic; sanity-check that reference charts still look correct. | `python scripts/drive_reference_charts.py [--output-dir DIR] [--write-csv]`. Requires `pip install pycontrolcharts[plotly]`. | HTML (and CSV if `--write-csv`) under `--output-dir` (default: `chart_output/`). |
| **drive_p215_imr_json.py** | Builds IMR (XmR) chart from USPC p215 data and writes JSON. | Quick check of JSON export or p215 limits. | `python scripts/drive_p215_imr_json.py`. No CLI options. | `chart_output/uspc_p215_imr.json`. |
| **drive_p_chart.py** | Demo p-chart: fixed dataset, plots to HTML and CSV. | Ad-hoc p-chart demo; no CLI. | `python scripts/drive_p_chart.py`. Requires plotly. | Writes `p_chart.html` and `p_chart.csv` in the **current working directory** (not under `chart_output/`). |

**drive_reference_charts.py** options:

- `--output-dir` — Directory for HTML (and CSV when `--write-csv`); default `chart_output`.
- `--write-csv` — Also write chart DataFrames to CSV (one file per chart).

## Development workflow

1. Fork the repo and create a branch for your change.
2. Make your changes; add or update tests for new behavior (new features should include tests).
3. Run tests, lint and format before submitting:
   ```bash
   pytest tests/ -v
   ruff check src/ tests/
   ruff format src/ tests/
   ```
4. Open a pull request. Target the default branch (e.g. `main`).
